The AI layer

I don't just use agents. I build the ones I work with.

Sixteen custom agent skills, one knowledge base they all read from, and a single rule: the agent verifies against the system, never against the claim. Pick a stage.

Review a screen against its whole data path

The agent walks one feature from the interface down through the API layers to the ERP and the database, then files what it finds — each finding classified by layer, severity and owner, so frontend and backend items route to different people automatically. It reads the shared knowledge base first, so it never re-derives a decision that was already made.

OutputFindings, classified
by layer & owner Reads firstThe knowledge base

Verify the fix, not the claim

When an item is marked fixed, this one audits it against the code as it stands today — and reproduces anything that depends on library or runtime behaviour rather than trusting the description. Genuinely fixed closes with the evidence attached; partially fixed goes back with the file, the line, and what is still missing.

Drive the real app, then check the backend

It signs in, enters data, saves, changes statuses — and then verifies each write against the actual backend and ERP rather than against the screen. That is the whole point: it catches the failure no interface test sees, where the form looked fine and nothing persisted. It cleans up the records it created.

Say what actually shipped, twice

It measures a period from the repositories and the task board, then checks what is genuinely live in production before a word goes out — so the employee version never announces a feature nobody can find. Two outputs from one pass: a delivery and KPI view for management, and a role-organised newsletter for the people who use it.
